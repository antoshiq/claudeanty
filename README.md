# claudeAnty — свой антидетект-браузер

Менеджер профилей поверх Google Chrome (или Chrome for Testing) и Camoufox (Firefox). Профили, прокси,
мобильный режим, пароли и 2FA, сценарии без кода, планировщик, резервные копии, локальный API.

## Установка

```powershell
pip install -r requirements.txt
python -m playwright install chromium   # запасной движок (Chrome for Testing)
python -m camoufox fetch                # только если нужны Camoufox-профили
python run.py
```

Рекомендуется установленный **Google Chrome**: Chromium-профили запускаются в нём (Настройки → Движок).
Если Chrome не установлен, используется Chrome for Testing из Playwright.

Данные хранятся в `data/` (SQLite + папка на каждый профиль). Локальный API: `http://127.0.0.1:3001`
(доступен только с вашего компьютера).

### Установщик (без Python)

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
```

Собирает `claudeAnty.exe` (PyInstaller, `packaging/claudeAnty.spec`) и установщик
`build\release\claudeAnty-setup-<версия>.exe` (Inno Setup 6, `packaging/installer.iss`) плюс файл `.sha256`.
Установщик ставит программу без прав администратора в `%LOCALAPPDATA%\Programs\claudeAnty`; данные — отдельно,
в `%LOCALAPPDATA%\claudeAnty\data` (обновление и удаление программы их не трогают; папка `data` рядом с exe —
портативный режим; `CLAUDEANTY_DATA` задаёт папку явно). Без Inno Setup собирается только портативная папка
`build\dist\claudeAnty`.

**Автообновление.** Версия — в `app/__init__.py`. Выпуск: поднять версию, собрать, создать релиз GitHub с тегом
`v<версия>` и приложить оба файла (`gh release create v1.6.0 build\release\*`). Установленные копии раз в сутки
проверяют последний релиз (Настройки → О программе), по кнопке скачивают установщик, сверяют SHA-256 и
обновляются тихо с перезапуском. Запуск из исходников обновляется через `git pull --ff-only` + `pip install`.

## Движок

**Google Chrome** (по умолчанию, если установлен) — тот же браузер, что у обычных людей: Widevine (DRM),
H.264/AAC/HEVC с аппаратным декодированием, PDF-просмотрщик. Chrome обновляется сам; claudeAnty сверяет его
версию с актуальной стабильной (при запуске и раз в 6 часов) и предупреждает, если он отстаёт — версия в UA
всегда равна версии запущенного браузера. Расширения в Chrome 137+ ставятся через CDP (`Extensions.loadUnpacked`),
потому что флаг `--load-extension` в обычном Chrome больше не работает.

**Chrome for Testing** (Playwright) — запасной вариант без Widevine; обновляется кнопкой «Обновить движок»
(`pip install -U playwright` + `playwright install chromium`).

## Защита отпечатка (Chromium)

**Всё, что Chromium умеет нативно, задаётся через CDP, а не JS** — подделку нечем обнаружить:
UA и Client Hints (версия = реальный движок), платформа, языки, ядра CPU, размер экрана, touch и DPR телефона,
таймзона, геолокация, тип сети и датчики телефона. Playwright сам ничего не эмулирует и запускает Chrome
без своих служебных флагов (`--enable-automation`, `--no-sandbox`, отключённые фичи и т.д.).

**Оставшиеся JS-подмены неотличимы от нативных** (память, WebGL, canvas, audio, шрифты, медиаустройства,
WebGPU): без `prototype`, с правильными `name`/`length`, «Illegal invocation» на прототипе, без кадров в стеке
ошибок, `toString` верен из любого контекста (в т.ч. iframe), никаких глобальных маркеров. Шум canvas и audio
стабилен (повторный вызов даёт то же самое) и не трогает однотонные заливки.

Шрифты: у профиля видны ровно шрифты его ОС. Чужие (Windows-шрифты у macOS-профиля) скрыты и в замерах,
и в `FontFace(local()).load()`; шрифты ОС профиля, которых нет на ПК (Helvetica Neue, Ubuntu…), «есть» —
замеры и рисование идут похожим установленным шрифтом (Arial метрически совпадает с Helvetica, Times New Roman —
с Times). `document.fonts.check()` не подменяется: настоящий Chrome для системных шрифтов всегда отвечает true.

Подмена работает и в Web Worker / SharedWorker / ServiceWorker, и в iframe — в том числе в iframe другого
сайта и в sandbox-iframe, которые Chrome выносит в отдельный процесс (иначе там видны системные таймзона,
число ядер и язык ПК; встроенная проверка это контролирует).

Проверено CreepJS (ПК, Windows): **headless 0%, stealth 0%, лжи не найдено**; like headless 25% — это
Android-only API и светлая тема, как у обычного Chrome на ПК. Телефон: headless 0%, stealth 0%, like headless 38%
(у сборки Chrome для ПК нет Android-API вроде ContactsManager — предел эмуляции телефона на ПК).

Встроенная проверка профиля (кнопка с отпечатком пальца) — 24 проверки, включая детекты подмены как в CreepJS,
Widevine и кодеки, iframe в отдельном процессе. Кнопка со щитом — автоотчёт внешних детекторов (pixelscan,
CreepJS, fingerprint.com, browserleaks, около двух минут); результат — в панели «Отпечаток».

**Управление браузером — Patchright** (Настройки → Движок): форк Playwright, который не включает на страницах
CDP-домены Runtime и Console, поэтому fingerprint.com больше не видит «Developer Tools». Скрипт подмены ставится
собственным CDP-клиентом (`Page.addScriptToEvaluateOnNewDocument` в каждую страницу и iframe до их кода), а не
через `add_init_script` Patchright — тот вставляет `<script>` в HTML, перехватывая все запросы и отключая кэш.
Обычный Playwright остаётся запасным вариантом.

Ошибки перехваченных функций (вызов с чужим `this`) имеют такой же стек, как у нативных: стек пересобирается с
точки вызова через исходный `Error.captureStackTrace`, а `e.stack` не читается (иначе `Error.prepareStackTrace`
страницы увидел бы наши кадры). Без расширения `WEBGL_debug_renderer_info` `getParameter` отдаёт `null`, как Chrome.

Ограничения: код страницы, выполняющийся *внутри* перехваченного вызова (например, `valueOf` аргумента
`getParameter`), видит кадр обёртки — средствами JS это не скрыть. Текст на canvas рисуется без подмены шрифта
(перехват `fillText` распознаёт pixelscan), поэтому у профилей «не Windows» скрытый шрифт ПК теоретически виден
по пикселям canvas; замеры текста (`measureText`, размеры элементов, `FontFace.load`) подменяются. На демо
fingerprint.com признак «Browser Tampering» нестабилен — при частых проверках с одного IP он появляется и у Chrome
без подмен.

**Стабильность между запусками:** каждая проверка сохраняет хэши canvas, картинки и параметров WebGL, audio,
шрифтов, navigator/экрана и Math и сравнивает с прошлой (отдельно с окном и без). Если что-то изменилось —
предупреждение с причиной: обновился Chrome, драйвер видеокарты или настройки профиля. Меню профиля →
«Проверить стабильность отпечатка» — три запуска подряд и сравнение.

Ограничение: когда профилем управляет внешний скрипт через API (Playwright/Puppeteer), сам скрипт может оставить
свои следы — это уже зависит от него.

## Мобильный режим

Подменяются: User-Agent и Client Hints (Android, модель), размер экрана и DPR, touch, `navigator.platform`
(`Linux armv81`), GPU (Adreno/Mali), `navigator.connection`, Battery API, события датчиков.

**Ограничения** (честно): подмена идёт через CDP и JS, поэтому сильный антифрод может её обнаружить.
Шрифты и часть аппаратного поведения остаются компьютерными — полностью скрыть, что это ПК, нельзя
ни в одном антидетект-браузере. Режим не заменяет реальное устройство и мобильный прокси.

Camoufox (Firefox) для мобильных профилей не используется: на Android почти все сидят в Chrome,
Firefox-«телефон» выглядел бы подозрительно.

## API

Все методы — на `http://127.0.0.1:3001`.

**Защита.** API отвечает только на запросы к `127.0.0.1` / `localhost` и отклоняет запросы со страниц сайтов
(заголовки `Origin`, `Sec-Fetch-Site`): иначе любой открытый в браузере сайт мог бы запускать профили, а через
DNS rebinding — читать пароли и коды 2FA. Скрипты (Python, Node, curl) это не затрагивает. Дополнительно можно
задать ключ (Настройки → Локальный API → «Сгенерировать»): тогда нужен заголовок `X-API-Key: <ключ>` или `?token=`.

### Playwright (Python)

```python
import httpx
from playwright.sync_api import sync_playwright

r = httpx.get("http://127.0.0.1:3001/profiles/1/start").json()
with sync_playwright() as p:
    browser = p.chromium.connect_over_cdp(r["ws_endpoint"])
    page = browser.contexts[0].new_page()
    page.goto("https://browserleaks.com")
httpx.get("http://127.0.0.1:3001/profiles/1/stop")
```

### Puppeteer

```js
const r = await (await fetch("http://127.0.0.1:3001/profiles/1/start")).json();
const browser = await puppeteer.connect({ browserWSEndpoint: r.ws_endpoint });
```

opts = webdriver.ChromeOptions()

## Проверка отпечатка

Откройте в профиле: `browserleaks.com` (WebRTC, Canvas, WebGL), `pixelscan.net`,
`abrahamjuliot.github.io/creepjs`. IP должен совпадать с прокси, без WebRTC-утечки, таймзона и язык — с IP.

**ОС профиля.** Браузер рисует текст и canvas шрифтами и рендером компьютера, поэтому профиль macOS/Linux на
Windows заметнее (fingerprint.com помечает его «Browser Tampering»). Новые профили по умолчанию получают ОС этого
ПК; форма профиля, массовое создание и проверка предупреждают о несовпадении.

## Здоровье профилей

Каждая проверка отпечатка и отчёт детекторов попадают в историю. Кнопка с пульсом над таблицей (или меню профиля →
«Здоровье профилей…») — график ✓ / ! / ✗ по дням для выбранных или всех профилей и последние проверки с пометкой
«▼ хуже». Если пункт стал ✗ или ✗ стало больше, чем в прошлый раз, приходит уведомление в Telegram
(«Здоровье профиля ухудшилось»). По расписанию — задача «Здоровье: отпечаток + детекторы» в Планировщике.

**Авто-метка «Бан».** Пока профиль запущен (и в сценариях), каждая открытая страница сверяется с правилами
(Настройки → Здоровье и бан): `facebook.com | url | /checkpoint`, `google.com | text | your account has been disabled`,
`instagram.com | captcha | 3` — капча на сайте 3 запуска подряд. Сработало — метка «Бан», причина в подсказке
метки и в панели «Отпечаток», уведомление в Telegram. Страница читается в изолированном мире — сайт этого не видит.
Снятие метки вручную обнуляет счётчики капч.

## Уникальность, журнал, планы прогрева

**Уникальность профилей** (меню профиля): профили одного ПК рисуют canvas, WebGL и audio одним железом, уникальными
их делает шум от seed профиля. Проверка сравнивает хэши между профилями: совпадение canvas / WebGL / audio (✗) —
сайт может связать аккаунты; общий выходной IP — тоже. «Снять заново» запускает профили без окна на пару секунд.

**Журнал активности** (кнопка с часами): запуски (с окном / без, прокси), остановки — сколько работал и какие сайты
открывал, сценарии, прогрев, проверки, смены IP и страны прокси, метки. Хранится 180 дней.

**Планы прогрева** (меню профиля → «План прогрева…»): Универсальный, Google / YouTube, Facebook, Instagram, TikTok.
Первые дни — общие сайты и поиски в Google, потом — сама площадка (без входа). Один день плана в сутки; задача
Планировщика «День плана прогрева» создаётся сразу. По окончании метка «Готов».

**Прокси перед запуском:** проверяется перед каждым запуском (кэш 2 минуты). Не отвечает — профиль не запускается;
сменил страну — предупреждение в журнал или отказ (Настройки → Прокси).

## Пароли, 2FA и перенос профилей

Пароли, секреты 2FA и заметки аккаунтов хранятся в базе зашифрованными ключом Windows (DPAPI) — без мастер-пароля,
но прочитать их может только ваша учётная запись на этом ПК. Ключи в `settings.json` (Telegram, капчи, SMS, API,
пароль копий) — тоже DPAPI (`"dpapi:…"`); старый файл с открытыми ключами шифруется при первом запуске.
В экспорт и резервные копии пароли попадают только по явной галочке.

**Шифрование файлов** (`crypto.encrypt_file`): AES-256-GCM блоками по 1 МБ (подмена, перестановка и обрезка
обнаруживаются). «Передать профиль» — ключ из пароля (scrypt), файл открывается на любом ПК с паролем.
Резервные копии — по умолчанию ключом Windows (только этот ПК и пользователь), можно паролем или без шифрования
(Настройки → Данные).

**Импорт аккаунтов строками** (Профили → Импорт → «Аккаунты строками»): `login:pass:2fa:proxy`, по профилю на
строку. Прокси сам содержит двоеточия (`host:port:user:pass`, `socks5://u:p@h:port`) — поле proxy забирает
остаток строки; если 2FA нет (`login:pass:host:port`), это определяется само. Свой формат — шаблоном
(`login|pass|email|email_pass|2fa|proxy`, `-` — пропустить поле); пароль с двоеточием — разделитель `|` или `;`.
Почта с паролем становится отдельным аккаунтом «Почта» для шага «Ждать письмо».

Cookies Chrome тоже зашифрованы ключом ПК: при экспорте они дополнительно сохраняются списком и при импорте
на другом компьютере добавляются заново (ключ Chrome в профиле сбрасывается). Сохранённые в самом Chrome пароли
на другой ПК не переносятся — для этого и есть «Пароли и 2FA».

## Сценарии

Шаги: открыть адрес, новая вкладка, кликнуть, ввести текст, нажать клавишу, подождать, ждать элемент, прокрутить,
решить капчу, извлечь в переменную, задать переменную, скриншот, блоки «Повторить N раз» и «Если…» (элемент
есть/нет, адрес содержит/не содержит, на странице есть текст, переменная равна) до «Конец блока».
Элемент — CSS-селектор, `text=Войти` или `xpath=//…`.

Подстановки: `{{login}}`, `{{password}}`, `{{totp}}` (`{{password:Google}}` — аккаунт Google), `{{name}}`, `{{id}}`,
`{{random:6}}`, `{{date}}`, колонки таблицы «Данные (CSV)» (строка на профиль — по колонке `profile` или по порядку)
и переменные. Извлечённые значения сохраняются в `data/rpa_results/*.csv`.

**Коды подтверждения.** «Ждать письмо с кодом» — ящик из «Пароли и 2FA» профиля (логин — адрес, пароль — пароль
приложения, IMAP-сервер по домену или вручную); ищет письма после начала сценария по отправителю и теме, код —
регулярным выражением (по умолчанию 4–8 цифр) → `{{email_code}}`. «Получить номер для SMS» (5sim или
sms-activate / совместимый API, ключ в Настройках → Сценарии) → `{{phone}}` и `{{phone_digits}}`; «Ждать SMS с
кодом» → `{{sms_code}}`. Код не пришёл или сценарий упал — номер отменяется.

**Запись:** кнопка «Записать» — работайте в профиле, клики, ввод, Enter, прокрутка, переходы и паузы станут шагами.
Пароли записываются как `{{password}}`, коды — `{{totp}}`, логин аккаунта — `{{login}}`.

**Как человек:** мышь — кривые Безье с разгоном и торможением, иногда перелёт; клик не в центр; печать с разной
скоростью и редкими исправленными опечатками, кириллица — настоящими нажатиями клавиш раскладки ЙЦУКЕН;
прокрутка «щелчками колеса» с инерцией. Используется в сценариях и прогреве.
